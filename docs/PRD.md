# 大学系级课程排课系统｜产品需求文档（PRD）

## 1. 文档信息

| 项目 | 决定 |
| --- | --- |
| 文档状态 | 需求已确认｜v1.1 |
| 适用范围 | 一个大学的单个系 |
| 系统界面语言 | 英文 |
| 主要用户 | 系教务排课老师 |
| 使用频率 | 每年约 2 次 |
| 首版范围 | 本文档确认的全部功能 |

## 2. 产品概述

这是一个可通过浏览器远程访问的大学系级排课系统，用于让多位排课老师协作、手工完成每周课程表。它将原有纸质总表替换为 3 张共享的年级总表，分别对应三个年级。

系统不做自动或 AI 排课。排课老师将课程班次拖入年级总表，分配教师、学生班级和教室；系统立即反馈冲突及规则问题。首版主要面向电脑浏览器。

## 3. 目标与非目标

### 3.1 产品目标

- 让排课老师在一个共享系统内手工完成完整课表。
- 在安排新增或变更时立即发现教室、教师和学生班级冲突。
- 检查排课限制；即使课表暂时不完美，也要让用户清楚了解所有问题。
- 支持按年级分工的多位老师协作，并处理跨年级课程及教师跨年级授课。
- 提供 3 张年级总表，以及按学生班级、教师和教室查看的课表。

### 3.2 首版不包含的内容

- 不做自动排课或 AI 排课。
- 不处理精确到个人的选课名单或选修课冲突；冲突只计算到学生班级/年级层级。
- 不对接学校统一登录。
- 不要求手机或平板完整编辑。
- 不提供课表历史、普通版本记录、修改审计或恢复到任意旧版本。
- 不提供 PDF 或 Excel 课表导出。
- 不发送邮件或短信通知。

## 4. 用户、权限与协作

### 4.1 角色

| 角色 | 权限 |
| --- | --- |
| 排课老师 | 查看和编辑全部课程、班次、学生班级、教师、教室、限制和已启用规则；可开启新一轮排课。 |
| 系统管理员 | 拥有排课老师的全部权限，另可创建、停用和重置账号。 |

所有排课老师拥有相同编辑权限；首版不按年级限制权限。

### 4.2 账号

- 每位协作老师使用独立用户名和密码登录。
- 管理员手工创建账号并设置初始用户名和密码。
- 用户可自行修改密码；管理员可重置忘记的密码。
- 因用户数量少且变动不频繁，首版不需要学校统一登录。

### 4.3 实时协作

- 对 3 张年级总表的新增、调整和删除需实时同步给其他用户。
- 校验必须基于所有年级总表的最新状态。
- 若两人同时修改同一个课程班次，后提交者必须看到“该班次已被他人更新”的提示；系统不得静默覆盖他人的修改。

## 5. 核心排课流程

1. 用户导入或维护课程、教师、教室和学生班级等基础资料。
2. `Teaching Members` 教学分配表决定课程班数和初始教师分配；排课老师在系统内维护上课模式、时长和教室要求。
3. 系统自动生成不可改名的课程班次，例如 `LEAD_01` 至 `LEAD_18`，并按导入表预先分配教师。
4. 用户将未排班次拖入对应年级总表的时间位置。
5. 用户指定或调整教师，选择一个或多个学生班级及一间教室；这些资料允许稍后补齐。
6. 系统立刻在课表及集中问题清单中标出冲突、规则问题、建议或未完成资料。
7. 用户可持续调整直至课表可用。任何问题都不会阻止继续排其他课程或保存草稿。

系统还应提供“候选位置”辅助：用户选择一个未排班次后，系统只高亮所有已启用规则均通过、且没有冲突、警告或不推荐提示的时间与教室组合。该功能仅辅助人工选择，不是自动排课；用户仍可手工安排到其他位置并查看问题原因。

## 6. 课表模型

### 6.1 时间网格

- 仅周一至周五排课。
- 每日可排课时间为 08:00–18:00。
- 最小排课粒度为 1 小时。
- 所有课程须整点开始、整点结束。
- 单次课程时长可为 2、3 或 4 小时；系统必须支持任意整小时的不同课程时长。
- 08:00 开课允许，但在相关规则开启时应提示为不推荐；尽量从 09:00 开始上课。

### 6.2 课程与班次

- 首版仅保存和展示课程编号，不需要完整课程名称。
- 系统按 `课程编号_01`、`课程编号_02` … 自动生成班次名称，用户不可修改。
- 同一课程的不同班次可有不同教师、学生班级和上课时间。
- 同一课程所有班次的单次时长、每周课次和教室要求相同。
- 每个班次只有一位教师和一间教室；首版不支持合授课或一个班次同时使用多间教室。
- 一个班次可关联一个或多个学生班级/年级。
- 每门课程由排课老师手工选择一个“主年级”，该课程的全部班次仅显示在这个主年级总表中；即使它服务其他年级的学生班级，也不在其他年级总表重复显示。跨年级冲突仍统一校验。

### 6.3 每周课次与教学周

- 一门课每周可上 1 次或 2 次。
- 每周 2 次的同一班次不得排在同一天。
- 每周 2 次的同一班次，教师和学生班级必须相同；教室可以不同。
- 排课通常每周循环。
- 一项课程安排可只在任意教学周区间内生效，例如第 1–4 周或第 5–8 周。
- 只有两项安排的教学周区间重叠时，才判定二者发生冲突。
- 总表不需要按具体教学周切换；有教学周限制的安排，可在详情中查看适用周次。

示例：某专业可在第 1–4 周上 `BED`、`DB`，第 5–8 周改上 `FED`、`PM`；如有需要，教师和教室可保持不变。

## 7. 数据维护与导入

### 7.1 课程

- `Teaching Members` Excel 是课程编号和课程班次初始教师分配的主要来源。
- 一门课程的总班数等于该课程所有教师分配行中正数 `# of grps teaching` 的总和。
- 单次时长、每周上课次数、最低教室容量和所需设施均由排课老师在系统内维护，不从教学分配表导入。
- 导入时，系统按 `# of grps teaching` 生成班次并预先分配教师；排课老师再安排学生班级、时间和教室，并可手工改教师。
- 导入前系统须校验计算出的课程班数及任何教师分配不一致问题。
- 不需要导入预览确认页；通过必要校验后，系统直接导入、更新数据并生成班次。
- 若用户把预分配给一位教师的班次改给另一位教师，系统应提示实际分配数量已与教学分配表不一致，但允许保存。
- `# of grps teaching = 0` 表示该教师不教此课程，不得生成课程—教师关联或未排班次；如该教师在其他课程有正数分配，仍应正常导入。

### 7.2 教师

- `Teaching Members` Excel 提供教师名单。
- 教师不可上课时段在系统中手工维护。
- 系统须保存和显示 `Staff Type`（如 FT/PT）。兼职教师（PT）通常时间限制更多，因此需优先排课。
- 未排班次清单中，分配给 PT 教师的班次应置顶并清晰标记。

#### 已确认的 `Teaching Members` 样例结构

已提供的 `Teaching Team 2026S1 (20-2-2026).xlsx` 定义了 `Teaching Members` 工作表的导入格式：共 213 条分配记录、52 个课程编号和 87 位教师。字段为 `Mod`、`Catalog`、`Lecturer`、`Staff Type`、`# of grps teaching`。

- `Mod` 是课程的唯一业务编号，用于课表展示和导入匹配。
- `Catalog` 不参与首版排课逻辑。
- 该表是课程、授课教师、课程总班数和每位教师负责班数的来源。例如 `LEAD` 各教师负责班数合计为 18；系统导入后自动完成这些班次到教师的初始分配，用户仍可调整。
- 下载文件中的其他工作表不属于导入约定。教师不可上课时段及地点限制仍在系统内手工维护。

### 7.3 学生班级

- 学生班级在系统内手工新增和维护。
- 每个班级至少记录班级编号、年级和专业。
- 共有 3 个年级，每个年级约有 16–18 个班级。
- 当前专业包括 AAA、CICTP、CSF、CLW、IT、IM。
- 不维护学生班级人数。教室容量只与课程中手工填写的最低容量比较，不自动合计关联班级人数。

### 7.4 教室

- 教室清单在系统内手工新增、编辑和停用；首版不导入教室 Excel。
- 每间教室至少维护：地址/名称、容量、是否有 Multi Projector、是否为 Lab、是否为 Smart Classroom。
- 教室地址采用 `block-level-room` 格式，例如 `31-05-10`；系统须能识别其中的 Block。
- Smart Classroom 一定具有 Multi Projector，但具有 Multi Projector 的教室不一定是 Smart Classroom。

### 7.5 导入行为

- 系统导入 `Teaching Members` 教学分配 Excel。
- 导入前应校验必填字段、格式及关联数据，并按行说明错误；错误数据不得静默进入系统。
- 再次导入相同唯一标识的数据时，系统自动更新已有记录；用户导入后可复核并手工修改。

## 8. 校验与规则引擎

### 8.1 规则行为

所有启用的规则在班次新增或修改时立即运行。即使某项严格规则被违反，用户仍可保留该安排；系统必须醒目标出安排并说明原因。问题不得阻止用户继续排课或保存草稿。

系统应提供集中问题清单，汇总所有问题，并能定位到对应课程安排。

所有预置规则均可由任一已登录用户启用或停用，但阈值固定。新增一种全新规则逻辑需要系统更新；规则实现应模块化，确保未来可快速增加规则且不影响现有数据和功能。

### 8.2 冲突和限制规则

| 规则 | 分类 | 预期行为 |
| --- | --- | --- |
| 教室时间冲突 | 严重冲突 | 同一教室在时间和教学周区间重叠时标出冲突。 |
| 教师时间冲突 | 严重冲突 | 同一教师在时间和教学周区间重叠时标出冲突。 |
| 学生班级时间冲突 | 严重冲突 | 同一学生班级在时间和教学周区间重叠时标出冲突。 |
| 教师不可上课时段 | 严重冲突 | 教师可维护具体星期/时段的不可用范围；排入该时段时标出冲突。 |
| 年级/学生班级禁排时段 | 严重冲突 | 用户可维护某年级不能上课的时段，例如周三全天或周一 16:00–18:00。 |
| 教室容量 | 严重冲突 | 教室容量低于课程最低容量时标出冲突。 |
| 教室设施 | 严重冲突 | 教室未同时满足课程全部设施要求时标出冲突。课程可以有多项必须条件。 |
| 午餐时间 | 严重冲突 | 每位教师和每个学生班级每天须在 12:00–14:00 内保留一段连续至少 1 小时的空档。 |
| 连续上课时长 | 严重冲突 | 教师或学生班级连续无空档的课时不得超过 4 小时；中间有至少 1 小时空档后重新计算。 |
| 每周两次课同日 | 严重冲突 | 每周上两次的同一班次不得排在同一天。 |
| 学生每日上课时长 | 高优先级警告 | 学生班级每日总课时超过 6 小时时标出警告。 |
| 教师每日授课时长 | 高优先级警告 | 教师每日总授课超过 7 小时时标出警告。 |
| 08:00 开课 | 建议 | 允许安排，但标出为不推荐。 |
| 紧接课程跨 Block | 建议 | 同一教师或学生班级两节课程完全相接且教室位于不同 Block 时提示移动风险；中间有至少 1 小时空档时不提示。 |
| 未完成安排 | 待完成事项 | 已放入课表但缺少教师、学生班级或教室时标出。 |

## 9. 界面需求

### 9.1 年级总表

- 主工作区为 3 张按年级区分的每周总表，延续现有纸质总表的排课方式。
- 每张总表有一个未排班次清单，用户从中拖动班次到时间位置。
- 未排班次清单支持按课程编号、教师、人员类型（FT/PT）、学生班级和专业搜索与筛选。
- 已排班次默认显示：课程编号与班次、教师姓名、学生班级、教室及问题状态。适用教学周在详情中查看，不占用默认课程块。
- 用户可手工编辑、移动或删除安排。
- `Master timetable` 是年级排课页的主要内容，页面首次进入时应占满全局导航以外的全部可用宽度；未排班次和 Inspector 不得永久预留左右栏宽。
- 页面顶部须提供带当前数量的 `Unscheduled sessions (N)` 开关。待排区关闭时完全不占总表宽度；打开后作为左侧抽屉显示搜索、筛选和可拖动课程，并可暂时缩小总表，关闭后总表立即恢复全宽。
- 页面顶部须提供 `Inspector` 开关。Inspector 打开时作为总表右侧浮动面板覆盖在工作区上方，不重新计算或压缩总表宽度；关闭后不得留下空白占位。
- 点击已排课程、待排课程的 `Schedule`／候选位置或集中问题项时，可自动打开 Inspector；用户必须始终能够明确关闭面板并返回全宽总览。
- 待排抽屉和 Inspector 均关闭时，大屏应优先在一个画面内显示周一至周五和 08:00–18:00；只有低于最低可读宽度的小窗口才允许总表内部横向滚动。
- 打开待排抽屉后仍须能够把课程拖到所有可见日期和整点时段；抽屉开关、Inspector 开关及关闭按钮必须支持鼠标与键盘操作。

### 9.2 课表查看

- Year 1、Year 2、Year 3 各一张年级总表。
- 首版不需要显示所有年级安排的全系总览；跨年级冲突在后台统一校验。
- 可按学生班级查看课表。
- 可按教师查看课表。
- 可按教室查看课表。

### 9.3 问题与反馈

- 课表须实时清楚显示冲突、警告、建议和未完成安排。
- 颜色标准：红色=严重冲突；黄色=高优先级警告；蓝色或灰色=建议与未完成安排。
- 集中问题清单汇总全部事项，并可跳转至相关课程安排。
- 用户为未排班次选择学生班级后，总表根据预分配教师、学生班级、教室、禁排时段、课程要求及全部启用规则，只高亮完全无问题的时间和教室候选。
- 导入错误、短暂网络中断或并发修改失败时，页面应清楚说明错误和下一步；不需要站外通知。

## 10. 新一轮排课与安全机制

- 系统只维护一份当前课表；不需按学期建立独立项目，也不需要日常查看历史课表。
- 任何已登录排课老师均可开启新一轮排课。
- 开始新一轮时清空当前安排、课程清单和已生成班次；保留教师、教室、学生班级和规则配置。
- 清空操作必须经过多次明确确认。
- 清空前系统自动保存一份可恢复备份，避免误清空；这不是日常可浏览的版本历史功能。

## 11. 验收标准

首版在排课老师能够完成下列工作时即可验收：

1. 使用独立账号登录，并实时协作编辑 3 张共享年级总表。
2. 从已校验的 `Teaching Members` Excel 导入课程与教师分配，并手工维护教室和修正后的数据。
3. 手工建立学生班级资料，包括年级和专业。
4. 按课程编号和班数生成班次，将其拖入年级总表，并立即或稍后补齐所需资源。
5. 维护本文定义的每日时间网格、可变课程时长、每周课次和教学周区间。
6. 实时查看并定位所有严重冲突、警告、建议和未完成安排。
7. 按年级总表、学生班级、教师或教室查看课表。
8. 安全地开始新一轮排课，同时保留基础资料和应急恢复备份。
9. 年级页默认以全宽 Master timetable 显示；待排抽屉和 Inspector 关闭时不占总表宽度，打开后仍能完成拖放、编辑和关闭面板。

本文未列出的新排课规则，可作为后续系统更新加入。
