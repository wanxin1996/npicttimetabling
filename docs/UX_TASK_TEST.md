# 1024×768 排课任务测试协议

本协议用于验证排课人员能否在常见的小型桌面视口中，独立完成一次真实的“找到课程—安排时间—确认保存”任务。它是正式发布的人类 UX 门槛，不能由源码检查、自动化浏览器或模拟数据替代。

## 一、通过标准

- 固定视口：`1024×768`；
- 参与者：五名未参与当前界面开发的真实用户，编号 `P1` 至 `P5`；
- 成功率：至少 `90%`。五人样本中，这等同于五人全部成功；
- 成功参与者完成时长的中位数：不超过 `60 秒`；
- 成功必须同时满足：课程已保存、参与者看见明确保存反馈、主持人没有介入。

## 二、测试前准备

1. 使用与正式数据结构一致的**隔离测试数据库**，不要连接生产数据库或正在使用的本地数据库。
2. 在浏览器开发者工具中把视口固定为 `1024×768`，缩放为 `100%`。
3. 打开 `Year timetables` 工作台，确认：
   - 顶部 `Workspace` 菜单可见；
   - `Unscheduled sessions` 默认展开，且至少有 20 张可测试课程；
   - 普通密度的总课表至少能同时看到三个工作日；极繁忙日期的课程卡不会被压缩到看不清文字，并可用左右按钮浏览；
   - `Inspector` 默认关闭，不遮挡课程或按钮。
4. 为每名参与者恢复同一份起始数据，不得让前一人的操作改变后一人的任务难度。
5. 主持人只朗读任务，不解释按钮、拖放位置或正确答案。

## 三、给参与者的唯一任务

> 请在 Year 1 中找到一门未安排的课程，把它放到你认为合适的日期和准确开始时间；如课程缺少 Student Group，请在 Inspector 中完成分配。确认保存成功后告诉我“完成”。

## 四、主持人记录规则

计时从任务朗读结束开始，到参与者看到保存反馈并说“完成”为止。

以下任一情况记为失败：

- 超过 180 秒仍未完成；
- 主持人需要指出按钮、日期、时间格、Student Group 或保存方法；
- 课程落在错误开始时间，或保存后没有出现在预期位置；
- 参与者没有看到保存成功/失败反馈；
- 页面遮挡导致关键按钮不可操作，且参与者无法自行恢复。

测试完成后，把原始结果如实写入 `docs/UX_TASK_TEST_RESULTS.json`，再运行：

```bash
cd web
npm run verify:ux-results
```

空模板、内部开发者自测或编造的五人数据都不算发布证据。

## 五、每轮结束后的补充观察

以下问题不改变主任务计时，但必须记录明显障碍：

1. 关闭 `Unscheduled sessions` 后，主课表是否立即取回全部宽度，且没有空白占位？
2. 打开浮动 `Inspector` 后，能否分配、更改、取消 Student Groups，并看见未保存草稿保护？
3. 同一小时已有课程时，能否准确拖到目标小时，而不会被卡片横向拥挤误导？
4. 课程卡是否一眼能读出“加粗课名、较小老师名、较小 Room、Student Groups”，且没有无用的 `2h/3h` 文本？
5. 顶部 `Workspace` 菜单在 1024px 宽度下是否仍可理解和操作？
6. 警告提示是否避开 `Inspector` 的按钮，并能自动消失或被关闭？

## 六、机器门槛与人工门槛的边界

`npm run verify:ux` 只检查当前 PRD 对应的源码契约，例如顶部 Workspace、默认展开待排课程、至少三天宽度数学、浮动 Inspector、卡片字号和 Student Groups 编辑能力。它适合放进每次自动回归。

`npm run verify:ux-results` 只验证真实任务测试记录，必须在五名参与者完成测试后执行。正式发布总门槛为：

```bash
cd web
npm run test:release:human
```
