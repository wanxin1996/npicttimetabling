# 本地真实数据验收副本

## 目的

正式排课数据库只作为只读来源。开发、浏览器测试和完整流程演练全部使用独立的 `timetabling-acceptance.db`；无论新增、修改、清空或恢复多少资料，都不会改变 `timetabling.db`。

该副本可能包含真实教师、课程、班级、教室和账号密码哈希，不能上传到 GitHub、网盘公开链接或发送给无权限人员。默认文件位于 `web/data/`，现有 Git 忽略规则会排除 `.db` 文件。

## 第一次建立副本

先停止正在使用验收数据库的本地服务器，然后在 `web` 目录执行：

```bash
node scripts/prepare-local-acceptance.mjs
```

脚本会：

1. 以只读、禁止写入方式打开正式 `data/timetabling.db`。
2. 检查 SQLite 文件完整性和全部外键。
3. 使用 SQLite 在线备份生成一致的副本，而不是直接复制可能仍有 WAL 写入的文件。
4. 只从副本清除旧浏览器会话，保留业务资料和账号。
5. 再次检查副本，并把文件权限限制为仅当前电脑账号可读写。

## 重置验收副本

确认验收服务器已经停止，并确认输出路径确实是 `timetabling-acceptance.db`，再执行：

```bash
node scripts/prepare-local-acceptance.mjs --replace
```

没有 `--replace` 时，脚本发现已有验收库会立即停止，不会覆盖。发现 `-wal`、`-shm` 或 `-journal` 文件时也会停止，提醒先关闭可能仍在写入的服务器。

如需把另一份已验证数据库作为来源，或把副本放到其他位置，可明确提供两个路径：

```bash
node scripts/prepare-local-acceptance.mjs --source /绝对路径/source.db --output /绝对路径/acceptance.db --replace
```

脚本拒绝来源和输出使用同一个路径。

## 启动验收系统

从 `web` 目录明确指定验收库，再启动本地开发服务器：

```bash
TIMETABLING_DATABASE_PATH="$PWD/data/timetabling-acceptance.db" npm run dev
```

打开 `http://localhost:3000/`。验收库中的旧登录会话已清除：如已有账号请重新登录；如果来源数据库没有账号，页面会要求建立第一个管理员。

不要在未设置 `TIMETABLING_DATABASE_PATH` 时进行验收，因为应用会回退到正式 `data/timetabling.db`。

## 完整流程验收清单

每次正式使用前，在可重置副本中依次完成并记录实际结果：

1. 登录管理员账号，确认教师、课程、班次、学生班级和教室数量与来源一致。
2. 重新导入 `Teaching Members`，确认重复导入更新资料但不重复生成教师、课程和班次。
3. 修改一门课程的时长、每周次数、主年级、教学周和多项教室要求；确认既有排课与问题自动刷新。
4. 建立或修改 Year 1、Year 2、Year 3 的学生班级和教室，并把班级关联到相应课程班次。
5. 在三张年级总表各安排至少一门课；分别使用候选时段、无拖动表单和拖动操作。
6. 制造并定位教师、学生班级和教室冲突，再调整到没有问题；确认红、黄、蓝问题状态和集中清单一致。
7. 按教师、学生班级和教室查看个人课表，确认跨年级课程都能出现。
8. 使用管理员页面下载完整系统备份；新增一个明显的测试资料后上传刚下载的备份，确认测试资料消失、全部旧会话失效，并能重新登录。
9. 检查三张年级总表、基础资料数量、问题数量、数据库完整性和外键；记录任何不符合预期的步骤。

## 结束与恢复

停止本地服务器后，再次运行带 `--replace` 的准备命令即可把所有验收修改恢复到正式数据库当前的只读副本状态。验收完成前不要删除正式数据库，也不要用验收库覆盖正式数据库。
