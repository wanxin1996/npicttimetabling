## 3. 可复验的本地证据

### 3.1 自动发布回归

在 `web/` 目录运行：

```bash
npm run test:release
```

命令按顺序执行 ESLint、Prisma schema/SQLite 建表 SQL 检查、UX 源码契约、一次生产构建、API CRUD、跨进程并发和性能脚本。构建只运行一次；五人结果不放进日常自动回归，避免空模板让每次开发检查失去区分度。

需要把真实用户结果也纳入发布决策时运行：

```bash
npm run test:release:human
```

当前这条人类总门槛会在 `verify:ux-results` 失败，这是诚实反映五人测试尚未采集，不是脚本故障。

### 3.2 数据库证据

数据库结构检查命令：

```bash
npm run db:check
```

`db:check` 不会打开正式数据库；它只验证 schema 能生成 SQLite DDL。2026-08-11 20:56（新加坡时间）的受控迁移核对显示当前本机数据为 87 名教师、52 门课程、374 个班次、0 个班次-学生关联和 19 个已排课次；`integrity_check=ok`、没有外键错误，唯一既有账号已迁移为 revision 1。迁移前安全副本、迁移前在线库和迁移后在线库在排除新增 `app_users.revision` 后的逐表规范摘要都为 `8436e6f6…94a8`，证明既有业务投影未被迁移改写。这只是本机快照，不代表 Railway 上线数据；测试和本地验收必须通过 `TIMETABLING_DATABASE_PATH` 使用隔离数据库。

### 3.3 API 与代码边界

- 当前共有 34 个 `src/app/api/**/route.ts` 路由模块；
- 年度工作台通过 `GET /api/schedule/workspace?year=…` 聚合课程、排课、教师、教室、学生班级和问题，避免页面串行请求产生撕裂快照；
- 关键写入使用事务、原子替换和跨进程写锁；
- 数据库路径由 `TIMETABLING_DATABASE_PATH` 控制，生产库位于 Railway 持久化 Volume。

### 3.4 UX 证据的限制

`npm run verify:ux` 是源码契约门槛，只能发现结构被删、宽度预算失效、资料表单焦点保护被移除或文档回退，不能证明拖放手感和真实用户理解。

最终 production build 已在隔离临时 SQLite、真实应用内浏览器和 `1024×768` 视口完成一次开发者验收：页面无整体横向溢出；教师、班级、教室、课程、班次、排课和个人课表关联一致；规则新增／删除会同步重算问题；停用教室仍保留历史课表并产生明确问题；两个管理员标签页用同一旧账号 revision 操作时严格显示赢家和 `ACCOUNT_CHANGED`，最新版按钮恢复焦点；普通排课账号看不到管理员清单。新增／编辑资料表单会进入第一个输入，成功后按稳定 ID 回到 Add、Edit 或状态按钮。该证据能证明本次构建的实际交互，但仍不能替代五位未参与开发者的理解测试。

五名真实用户必须严格执行 [UX_TASK_TEST.md](UX_TASK_TEST.md)：固定 `1024×768`，成功率至少 90%，成功样本中位时长不超过 60 秒，且成功样本无主持人介入并看到保存反馈。当前结果为空，所以本项仍未通过。

## 4. Railway 线上验收

部署后先运行：

```bash
cd web
npm run verify:deployment -- https://你的域名.up.railway.app
```

随后必须人工完成：

1. 健康检查证明应用运行且数据库可查询，同时不泄露记录数量、路径或账号资料；
2. 年度工作台在 1024×768 至少三天同屏，待排区和 Inspector 可独立开关；
3. 新建或移动课程后强制刷新，数据仍存在；
4. 重启 Railway 服务后再次确认该数据仍存在；
5. 备份、下载和一次受控恢复演练成功；
6. 浏览器控制台无阻断性错误，通知不遮挡 Inspector 关键按钮。

这些线上证据当前未采集，不能用本地测试结果替代。

## 5. 正式发布判定

只有以下三组证据全部通过，才允许把 MVP 标记为“正式发布通过”：

1. `npm run test:release` 通过；
2. 五名真实用户结果通过 `npm run verify:ux-results`；
3. Railway 部署检查、人工冒烟、重启持久化和恢复演练通过。

任一项缺失时，应保持“发布候选 / 验收未完成”状态，并在发布说明中明确剩余风险。
